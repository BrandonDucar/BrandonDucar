# Get Help With A DreamNet Product

Choose a product in the [directory](https://brandonducar.github.io/BrandonDucar/)
and follow its README for setup, requirements, license and current limitations.
Products are independently scoped. Optional integrations do not require access
to DreamNet's private operational monorepo or transfer another product's authority.

## Choose A Conversation

- [Product help or bug report](https://github.com/BrandonDucar/BrandonDucar/issues/new?template=01-product-help.yml): include the product, version, goal, expected result and actual result.
- [Integration proposal](https://github.com/BrandonDucar/BrandonDucar/issues/new?template=02-integration.yml): name both tools, the user outcome and the smallest example that would prove it works.
- [Directory correction](https://github.com/BrandonDucar/BrandonDucar/issues/new?template=03-directory.yml): report a broken link, misleading claim, accessibility issue or outdated screenshot.
- [General discussion](https://github.com/BrandonDucar/Dreamnet/discussions): questions about public contracts and how projects fit together.

Search existing issues first. If a product already has a matching issue, add a
reproduction there instead of opening a duplicate. This profile repository is a
fallback intake point, not a replacement for each product's issue tracker. For
forks, consult the upstream contribution guide before proposing upstream changes.

## Keep Public Reports Safe

GitHub issues and discussions here are public. Use synthetic examples. Do not
upload API keys, environment files, access tokens, private repository contents,
customer records, private conversations or unredacted logs. Remove sensitive
values before attaching screenshots and fixtures.

Do not describe an exploitable vulnerability in a public issue. Use the affected
repository's SECURITY.md or its Security tab's private reporting option when
available. If neither is available, request a private contact method without
including exploit details. Do not assume a confidential channel exists.

## What Happens Next

Maintainers can ask for a reproduction, identify the owning repository, link an
existing issue or explain an unsupported use case. A submitted request is not
an accepted roadmap commitment, a deployment approval or a guaranteed response
time. Keep follow-up evidence in the same conversation so others can reproduce it.
